# 파랜드 택틱스 1을 참고한 웹 전술 RPG 조사

조사일: 2026-10-02. 이번 작업은 자료 조사와 구현 방향 정리이며 게임 코드는 변경하지 않았다.

## 결론

현재 GH ARCADE의 React + TypeScript + Canvas 2D 구조에서 구현하는 방향을 추천한다. 첫 제작 목표는 **쿼터뷰 전장, 역할이 다른 동료 4명, 전투 3개, 맵 위 대화, 성장과 저장이 연결되는 짧은 싱글플레이 RPG**다. 이를 먼저 완주할 수 있게 만든 뒤 캠페인을 확장한다.

원작에서 참고할 중심은 전투 규칙만이 아니다. 작은 캐릭터들이 같은 맵 위에서 대화하고 싸우는 연속성, 동료마다 다른 전투 역할, 전투를 거치며 성장하는 애착이 함께 필요하다. 캐릭터·세계관·그림·음악은 새 작품에 맞춰 제작하는 방향으로 제안한다.

## 1. 조사 대상과 자료의 한계

국내 파랜드 택틱스 1을 다루는 [한국어 공략](https://gamemom.tistory.com/98)은 이를 파랜드 사가 1로 병기한다. 일본 원제는 **ファーランドサーガ / Farland Saga**다. **時の道標 / Toki no Michishirube**는 2편이므로 1편 조사에 섞지 않았다.

[공식 복각 사이트](https://city-connection.co.jp/s-tribute/fs1_2/)와 [1편 Steam 소개](https://store.steampowered.com/app/3519180/?l=english)는 화면 구성과 이야기 진행을 확인하는 1차 자료다. 다만 이 제품은 세가 새턴판 기반 복각이므로, 국내 PC판의 세부 규칙을 모두 같다고 단정하지 않는다. 복각의 음성·되감기·경험치 배수 기능도 PC 원작 기능으로 취급하지 않는다.

원작 PC판의 모든 수치와 규칙을 확인할 수 있는 설명서는 이번 조사에서 확보하지 못했다. 아래 고저차·돌진의 상세 조건은 새턴판 플레이 기록에서 확인한 내용으로, PC판에 그대로 적용되는지는 추가 검증이 필요하다. 실제 플레이 영상의 프레임별 분석이나 직접 플레이는 수행하지 않았다.

## 2. 확인된 특징과 제작에 주는 의미

| 특징 | 확인 근거 | 제작에 반영할 방향 |
| --- | --- | --- |
| 쿼터뷰 맵 위 대화와 전투 | 공식 사이트는 영상 장면을 제외한 이야기가 쿼터뷰 맵에서 진행된다고 설명 | 전투 맵에 대화 이벤트를 배치하고 전투 진입을 연결 |
| 진지함과 코미디가 섞인 동료 이야기 | 공식 소개와 Steam 설명 | 캐릭터 말투와 관계를 먼저 정하고 짧은 대화에서도 드러내기 |
| 스테이지별 목표 | 한국어 공략에 적 전멸, 특정 적 격파 등이 기재 | 승리 조건을 데이터로 분리하고 전투마다 목표 표시 |
| 좁은 길을 활용하는 전술 | 한국어 공략 초반의 다리 유인 전략 | 첫 맵부터 다리·병목을 넣어 위치 선정의 의미 만들기 |
| 동료 합류와 보조 행동을 통한 성장 | 한국어 공략의 힐러 합류, 보조마법·아이템 경험치 설명 | 회복·지원 역할도 성장할 수 있도록 설계 |
| 이동과 공격에 영향을 주는 높이 | 새턴판 플레이 기록 | 타일 높이, 오를 수 있는 단차, 높이 피해 보정 도입 |
| 이동 경로와 연결된 돌진 공격 | 새턴판 플레이 기록 | 이동 거리만 보지 말고 경로의 직선 구간과 단차까지 기록 |
| 범위 마법, 경험치, 클래스 체인지 | TGL 공식 PC 지원 문서의 수정 내역 | 스킬 범위와 성장 데이터를 별도로 관리 |

근거: [공식 소개](https://city-connection.co.jp/s-tribute/fs1_2/), [국내 PC판 스테이지 공략](https://gamemom.tistory.com/98), [새턴판 플레이 기록](https://ww5.tiki.ne.jp/~gakurou/game/ss/frlndsg.html), [TGL 공식 PC 지원 문서](https://www.entergram.co.jp/support/faq_saga.html).

새턴판 기록은 직선으로 3칸 이상 이동한 뒤 공격하면 돌진이 발생하며 큰 단차가 있으면 불가능하다고 설명한다. 높은 곳에서 공격하면 피해가 증가하고, 낮은 곳에서는 감소한다고도 기록한다. 정확한 배율·거리 측정 방식은 확인되지 않았다. 이 수치를 원작의 확정 규칙으로 코드에 고정하지 않는다. [출처](https://ww5.tiki.ne.jp/~gakurou/game/ss/frlndsg.html)

## 3. 우리가 만들 첫 버전 — 아래 수량과 규칙은 제안

### 플레이 흐름

시작 → 맵 위 대화 → 승리 목표 안내 → 전투 → 보상·레벨 상승 → 다음 대화 → 장비 정비·저장 → 다음 전투.

첫 버전의 완료 기준은 사용자가 세 전투를 끝까지 진행하고, 저장 후 다시 열어 이어 할 수 있는 것이다.

| 항목 | 제안 범위 |
| --- | --- |
| 플레이 | 싱글플레이, PC 마우스 우선, 태블릿 터치 대응 |
| 동료 | 검사, 창병, 마법사, 치유사 4명 |
| 적 | 근접병, 원거리병, 적 마법사, 보스 등 4~5종 |
| 전장 | 약 12×12~16×16칸, 높이 0~2단계 |
| 전투 | 다리 전투, 고지 전투, 보스 전투 3개 |
| 행동 | 이동, 공격, 스킬, 아이템, 대기 |
| 스킬 | 단일 공격, 직선 공격, 범위 공격, 회복, 지원 등 6~8개 |
| 성장 | 개인 레벨·경험치, 제한된 장비 교체, 스킬 해금 |
| 진행 | 초반부터 끝까지 연결되는 짧은 이야기 |
| 저장 | 전투 사이 자동 저장, 버전이 있는 저장 데이터 |

아군 진영과 적 진영이 교대로 행동하고, 아군 차례에 유닛별로 이동 1회와 행동 1회를 허용하는 규칙을 첫 설계안으로 제안한다. 이는 이번 조사에서 PC 원작의 상세 행동 순서를 확정한 결과가 아니다. 공격 후 이동 허용 여부, 아군 통과, 반격, 방향 보정, 비행 이동은 제작 전에 정할 항목이다.

### 전투 3개의 목적

1. **다리 전투:** 검사와 치유사의 협력, 병목 유인, 기본 조작을 익힌다.
2. **고지 전투:** 높이 차이와 원거리 적, 직선 돌진의 장단점을 경험한다.
3. **보스 전투:** 적 지원병과 범위 마법을 배치하고, 특정 보스 격파를 목표로 삼는다.

각 맵은 단순히 적 체력만 늘리지 않고 다른 전술을 요구해야 한다. 완성 후 플레이 시간과 난이도는 실제 플레이로 측정한다.

## 4. 현재 프로젝트에서 구현하는 방법

저장소의 `package.json`, `README.md`, `src/platform/gameRegistry.ts`, `src/games/three-kingdoms/README.md`를 확인했다. 기존 프로젝트에 React 19, TypeScript, Vite, Canvas 게임 구조와 턴제 게임이 있으므로 별도 엔진 도입 없이 시작할 수 있다.

제안 구조:

```text
src/games/fantasy-tactics/
  game/
    types.ts           전투·유닛·타일·스킬 정의
    grid.ts            사각 격자, 화면 좌표 변환
    movement.ts        이동 가능 범위, 높이, 경로 비용
    commands.ts        이동·공격·스킬 명령 검증과 실행
    combat.ts          피해·회복·효과·경험치
    turn.ts            진영 전환과 행동 상태
    ai.ts              공통 명령을 사용하는 적 의사결정
    objectives.ts      승패와 전투 이벤트 조건
    campaign.ts        동료 합류·스테이지 진행
    save.ts            저장 검증과 버전 관리
  data/                동료·적·스킬·맵·대화 데이터
  rendering/           쿼터뷰 그리기·애니메이션·카메라
  components/          상태창·명령 메뉴·대화·정비 화면
```

기존 삼국지에서 참고할 것은 규칙/연출 분리, AI와 플레이어의 공통 명령 처리, 시드 난수, 턴 처리 구조다. 해당 게임은 육각 지도이므로 좌표·경로 탐색·전투 규칙을 그대로 복사하지 않고 새 사각 격자에 맞춘다.

전투 계산은 논리 좌표 `(x, y, height)`로 하고, 쿼터뷰는 그리기 단계에서 변환한다. 화면상 높이에 가려진 타일 선택, 캐릭터와 지형의 앞뒤 순서, 이동 경로 표시가 주요 구현 난점이다.

첫 렌더러는 Canvas 2D를 추천한다. React는 상태창·대화·버튼을 맡는다. 실제 3D 회전이 필요한지 결정된 뒤 Three.js를 검토한다. 지도 크기와 스프라이트 수가 정해진 다음 대표 맵으로 성능을 측정한다.

맵·스킬·대화는 데이터로 분리한다. 전투마다 엔진 코드를 추가해야 하는 구조를 피해야 캠페인을 늘릴 수 있다. 간단한 내부 맵 편집 도구는 전투 한 개가 완성된 뒤 도입한다.

## 5. 그래픽과 사운드 제작

파랜드 분위기를 만드는 시각 요소로는 밝은 색의 작은 캐릭터, 다이아몬드 형태의 바닥 타일, 단차가 보이는 지형, 큰 초상과 대화창, 알아보기 쉬운 마법 효과를 제안한다. 이는 공식 이미지와 소개를 참고한 제작 해석이다.

처음부터 임시 도형으로만 모든 전투를 만드는 대신, **동료 1명 + 타일 세트 1개 + 대화창 1개**를 먼저 제작해 대표 화면의 크기와 화풍을 확인한다. 확정한 규격을 나머지 에셋에 적용한다.

- 캐릭터: 방향별 대기·이동·공격·피격. 스킬은 몸동작과 효과를 분리해 재사용.
- 지형: 잔디, 길, 물, 다리, 절벽, 높이 옆면과 소품.
- 초상: 동료마다 기본 표정, 필요 장면에 한해 추가 표정.
- 효과: 공격·회복·상태 효과를 색과 모양으로 구분.
- 음향: 전투 음악, 대화 음악, 이동·타격·회복·UI 효과음.

임시 지형 후보로 [Kenney Isometric Blocks](https://kenney-assets.itch.io/isometric-blocks)가 있다. 제작자 페이지는 CC0이며 상업적 사용도 가능하다고 명시한다. 이것은 프로토타입용 후보이고 파랜드의 픽셀 화풍을 그대로 만족시키는 완성 에셋이라고 보지는 않는다.

## 6. 개발 순서와 확인 기준

| 단계 | 산출물 | 통과 기준 |
| --- | --- | --- |
| 1. 규칙과 대표 화면 | 행동 규칙 문서, 캐릭터·타일·UI 샘플 | 선택한 타일과 행동 가능 범위가 명확하게 보임 |
| 2. 전투 한 판 | 이동·공격·회복·적 AI·승패 | 시작부터 승리/패배까지 진행 가능 |
| 3. 파랜드식 전술 요소 | 단차, 범위 마법, 돌진 | 미리보기와 실제 판정이 일치 |
| 4. RPG 연결 | 대화·보상·성장·저장·다음 전투 | 새로고침 후 진행을 복구하고 다음 전투 진입 |
| 5. 짧은 캠페인 | 전투 3개와 이야기 | 처음부터 끝까지 플레이 가능, 역할별 활약 확인 |
| 6. 확장 | 추가 동료·스킬·맵·이벤트 | 데이터 추가로 기존 규칙 내 콘텐츠 제작 가능 |

필요한 규칙 검증은 이동 제한·막힌 경로·단차·범위 경계·돌진 조건·행동 중복 방지·승패·저장 복구다. 브라우저에서는 높은 타일 선택, 가려진 유닛 표시, 취소 조작, 애니메이션 중 연속 클릭, 터치와 화면 크기를 확인한다.

지원 행동에도 경험치를 주되, 이미 완전히 회복된 대상에게 반복 회복만 해서 성장하는 상황은 제안 규칙에서 제한한다. 무의미한 반복보다 전투 참가와 유효한 지원에 보상을 주는 방향으로 조정한다.

## 7. 구현 전 남은 결정

- 원작의 조작감을 어느 정도 따를지: 행동 순서, 반격, 아군 통과, 방향.
- 새 작품의 세계관·주인공·동료 관계와 제목.
- 픽셀 스프라이트 또는 손으로 그린 작은 캐릭터 중 화풍.
- 전투 불능 처리와 패배 후 재도전, 난이도.
- PC판 고저차·돌진·마법 범위의 세부 규칙 추가 확인.

정확한 개발 기간은 에셋 제작 수준과 캠페인 분량을 정하기 전에는 산정하지 않는다. 가장 먼저 확인할 것은 전투 한 판의 조작감과 대표 화면의 품질이다.
