# 하츄핑 두더지

3×3 구멍에서 튀어나오는 두더지를 30초 동안 두드린다.

## 난이도를 "빠르기"가 아니라 "동시에 몇 마리"로 나눴다

| | 동시에 | 머무는 시간 | 숨는 시간 |
|---|---|---|---|
| 쉬움 | 1마리 | 1.1~1.6초 | 0.65~1.3초 |
| 보통 | 2마리 | 0.75~1.15초 | 0.45~0.95초 |
| 어려움 | 3마리 | 0.5~0.85초 | 0.3~0.7초 |

머무는 시간만 줄이면 어려움은 그냥 **반응 속도 시험**이 된다. 동시에 나오는 수를 같이 올리면
"어느 쪽을 먼저 칠까"가 생겨서, 빠른 손뿐 아니라 눈의 우선순위가 점수를 가른다.

## 한 판 안에서도 세 번 빨라진다

`roundFor`가 남은 시간으로 라운드를 정하고(30~20초 / 20~10초 / 10~0초), `ROUND_SPEED`가
두더지의 체류·대기 시간에 1 → 0.88 → 0.76을 곱한다. 30초 내내 같은 속도면 후반이 지루하다.
끝이 다가올수록 빨라지는 쪽이 마지막 10초를 긴장하게 만든다.

난이도 설정은 전체를 옮기고, 라운드는 한 판 안의 가속을 맡는다. 두 축이 곱해지므로 어려움의
3라운드가 이 게임에서 가장 빠른 구간이다.

## 연속 타격은 계단식으로

`COMBO_TIERS`가 5연타에서 1.5배, 10연타에서 2배, 20연타에서 3배. 한 대마다 조금씩 오르는
방식이 아니라 계단인 이유는, **다음 칸이 눈에 보여야** 참고 조준하기 때문이다. 배열은 높은
단계부터 적혀 있어서 `find`가 첫 번째로 맞는 것을 고른다 — 순서를 뒤집으면 20연타에도 1.5배가
나온다.

## 키보드로도 친다

`MOLE_KEYS`가 `q w e / a s d / z x c`. 3×3 구멍이 키보드 위에서 같은 모양으로 놓인다. 마우스가
없거나 손이 느린 사람을 위한 길이기도 하고, 테스트에서 판을 자동으로 돌릴 때도 쓴다.

## 오늘의 도전이 난이도를 정해 준다

이 게임이 플랫폼의 `settingsStore.extra.difficulty`를 읽는 **첫 번째** 게임이었다. 허브가 "어려움
30점"을 내면 게임이 그 난이도로 열린다. 이 연결이 없으면 도전은 조용히 달성 불가가 된다 —
나중에 색깔 맞추기와 룬 레인저도 같은 방식으로 맞췄고, 지금은 테스트가 셋 다 지킨다.

## 구성

| 파일 | 하는 일 |
|---|---|
| `game/constants.ts` | 격자, 난이도, 콤보, 라운드 가속 |
| `game/engine.ts` | 두더지 등장·퇴장, 판정, 점수 |
| `game/renderer.ts` | 캔버스 그리기 |
| `game/moleImage.ts` | 두더지 그림 생성 |
| `hooks/useWhackAMoleEngine.ts` | React 연결 |

## 아직 하지 않은 것

- 결과 화면(`components/GameOverWithLeaderboard.tsx`)이 색깔 맞추기와 같은 구조다 — 점수, 난이도별 TOP 10, 명중률, 보상.
  이쪽은 키트의 `GameDialog`를 쓰고 저쪽은 자체 마크업이라, 합치려면 먼저 저쪽을 키트로 옮겨야 한다.
- 때리면 안 되는 두더지가 없다. 넣으면 "무조건 빨리"가 "보고 치기"로 바뀐다.
