# 하츄핑 색깔 맞추기

말한 색의 물감통을 제한 시간 안에 고르는 30초 게임.

## 색만으로 구별하게 만들지 않았다

`COLOR_PALETTE`의 색마다 `pattern`이 붙어 있다 — 빨강은 점, 파랑은 줄무늬, 노랑은 격자. 이
무늬는 **문제와 물감통 양쪽에 똑같이** 그려진다. 색각 이상이 있는 아이가 빨강과 초록을 구별하지
못해도 "점이 찍힌 쪽"으로 맞힐 수 있다. 색 이름만으로 맞히는 게임에서 색을 못 보면 게임이 아니라
벽이 된다.

글자 색(`ink`)도 색마다 따로 정했다. 노랑과 하늘색 위에는 검정, 나머지에는 흰색. 대비를 눈으로
확인하고 박아 둔 값이라 새 색을 추가할 때 같이 정해야 한다.

## 틀리면 목숨이 아니라 시간을 뺏는다

오답은 `WRONG_PENALTY_SECONDS = 1.5`만큼 전체 시계를 깎는다. 판이 끝나지는 않는다. 그리고
**같은 통을 다시 눌러도 두 번 세지 않는다** — 아이가 당황해서 같은 자리를 연타하는 것은 새로운
실수가 아니다. 이미 깜빡이고 있는 통은 `wrongFlashTimers`에 들어 있어 그대로 무시된다.

시간 초과도 오답으로 치되 시간은 깎지 않는다. 가만히 있는 것과 잘못 누르는 것의 대가가 다르다.

## 같은 색이 연달아 나오지 않는다

`buildRound`는 직전 정답을 후보에서 뺀다. 같은 색이 두 번 나오면 **탭이 안 먹은 것처럼 보인다.**
맞혔는데 화면이 그대로면 아이는 다시 누르고, 그건 오답 처리된다. 뺄 수 있을 때만 빼고, 후보가
전부 직전 색이면 그냥 쓴다.

## 난이도는 세 숫자만 바꾼다

| | 통 개수 | 최대 통 | 답할 시간 |
|---|---|---|---|
| 쉬움 | 3 | 4 | 3.2초 |
| 보통 | 4 | 5 | 2.4초 |
| 어려움 | 5 | 6 | 1.8초 |

판 길이는 셋 다 30초로 같다. 어려운 판이 더 짧아지면 "어려운데 짧기까지" 하고, 더 길어지면
벌이 된다. 레벨이 오르면 답할 시간이 10%씩 줄지만 처음의 60% 아래로는 내려가지 않는다
(`MIN_TIME_FACTOR`). 통은 레벨 3과 5에서 하나씩만 는다.

난이도는 허브의 오늘의 도전이 정해 줄 수 있다. `settingsStore`의 `extra.difficulty`를 먼저 읽고,
없으면 게임 자체 설정을 쓴다. 이 연결이 끊기면 도전이 "어려움"으로 뜬 날 아무리 잘해도 조용히
인정되지 않는다 — `tests/meta-registry.test.mjs`가 소스 수준에서 지킨다.

## 구성

| 파일 | 하는 일 |
|---|---|
| `game/constants.ts` | 색·무늬·난이도·점수. 균형은 전부 여기 |
| `game/engine.ts` | 라운드 생성, 판정, 레벨, HUD 발행 |
| `game/sound.ts` | 정답·오답·레벨업 소리 |
| `components/` | 시작 메뉴, 물감통, 일시정지, 결과 |

## 아직 하지 않은 것

- `game/sound.ts`가 키트의 `createGameSound`를 쓰지 않고 자체 AudioContext를 연다.
- 결과 화면(`components/GameOverWithLeaderboard.tsx`)이 두더지 게임과 같은 구조인데, 저쪽은 키트의
  `GameDialog`를 쓰고 이쪽은 자체 마크업이다. 일시정지 대화상자도 마찬가지다.
- 색 이름을 읽어 주는 음성이 없다. 글자를 못 읽는 아이는 아직 혼자 못 한다.
