# 하츄핑 슬리더

9000×9000 세계에서 별을 먹고 자라며 다른 뱀과 겨루는 게임. 아케이드에서 가장 무거운 실시간
시뮬레이션이다(봇 48~72마리 + 별 1700개).

## 점수가 곧 크기, 그런데 제곱근으로

```ts
radiusForScore(score) = R_MIN + GROWTH_K * sqrt(score)
```

점수에 비례해 굵어지면 2000점짜리 뱀은 화면을 꽉 채워서 아무것도 보이지 않는다. 제곱근 곡선은
**초반에는 눈에 띄게 자라고, 후반에는 거의 자라지 않는다.** 길이(`segmentCountForScore`)는 반대로
점수에 선형이라 계속 늘어난다. 자란 느낌은 길이가 주고, 조작 가능성은 굵기가 지킨다.

커질수록 회전이 느려지는 것(`turnRateForRadius`)이 이 게임의 유일한 패널티다. 1등이 된 순간
무적이 되지 않게 하는 장치고, 작은 뱀이 큰 뱀을 잡는 길이기도 하다.

## 죽으면 먹은 것을 전부 돌려준다

`DEATH_DROP_RECOVERY_RATIO = 1.0`. 죽은 뱀의 점수는 100% 별로 흩어진다. 세계의 별 총량이
보존되므로, 큰 뱀끼리 싸운 자리에 누가 먼저 도착하느냐가 판을 뒤집는 사건이 된다. 비율을 낮추면
싸움이 서로 손해인 행동이 되고, 다들 멀리 떨어져서 별만 줍는다.

다만 흩뿌리는 별의 개수에는 상한(80)이 있다. 상한이 없으면 3000점짜리가 죽는 순간 별 750개가
한자리에 생겨 프레임이 떨어진다.

## 정면충돌을 양쪽 다 죽인다

머리와 머리가 부딪히면 누가 들이받았는지 정하기 어렵다. `HEAD_ON_ALIGNMENT_EPSILON = 0.12`는
"둘의 정렬 점수가 이만큼 가까우면 서로 죽인 것으로 친다"는 선이다. 한쪽만 죽이면 그 판정이
프레임 순서나 배열 순서에 따라 갈리고, 플레이어 눈에는 그냥 억울한 죽음으로 보인다.

자기 몸과의 충돌은 머리 근처 `SELF_COLLISION_SKIP_FACTOR = 2.5` 반지름만큼 무시한다. 그러지
않으면 급회전할 때마다 자기 목에 걸려 죽는다.

## 1700개 별과 72마리 뱀을 매 프레임 훑지 않는다

`spatialGrid.ts`의 공간 해시 격자 두 개 — 별용(셀 140), 몸통용(셀 100). 전부 대 전부 비교는
뱀 72마리 × 평균 100마디 = 7200개 점에 대해 불가능하다. 격자는 매 프레임 다시 만든다.
움직이는 점을 격자 안에서 갱신하는 것보다 새로 짓는 쪽이 빠르고 틀릴 여지가 적다.

봇은 매 프레임 생각하지 않는다. `BOT_THINK_INTERVAL` 0.10~0.16초마다 한 번이고, 봇마다 시각이
어긋나 있어 같은 프레임에 몰리지 않는다.

## 레벨업은 "무엇을 포기할까"를 묻는다

`progression.ts`의 강화 셋 — 바람 걸음(기동), 별의 인력(수집), 오래 달리기(부스트).
포인트는 레벨마다 하나뿐이고 상한은 레벨 20이다. 한 판 안에서 셋을 고루 올릴 시간은
없으니, 무엇을 먼저 올릴지가 곧 이번 판의 성격이 된다.

경험치 곡선은 `40 + 20(L-1) + 4(L-1)²`로 초반이 빠르고 후반이 가파르다. 강화가 쌓일수록 한 판의 힘이 커지니 레벨 간격도 같이 벌린다.

## 구성

| 파일 | 하는 일 |
|---|---|
| `game/constants.ts` | 균형 숫자 전부 |
| `game/growth.ts` | 점수 → 크기·길이·회전 속도 곡선 |
| `game/collision.ts` | 별 줍기, 몸통 충돌, 정면충돌 판정 |
| `game/spatialGrid.ts` | 공간 해시 격자 |
| `game/botAI.ts` | 봇의 목표 선택과 회피 |
| `game/progression.ts` | 레벨과 강화 |
| `game/world.ts` | 별 보충, 봇 생성·부활 |
| `hooks/useGameEngine.ts` | React 연결 |

## 아직 하지 않은 것

- 봇은 모두 같은 성격이다. 공격적인 봇과 겁 많은 봇이 섞이면 세계가 더 살아 있게 느껴진다.
- 멀티플레이는 없다. 순위표의 다른 이름은 전부 봇이다(`SNAKE_NAME_POOL`).
